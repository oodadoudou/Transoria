# Glossary Review Module

Status: Active module documentation
Last reviewed: 2026-06-28

## Purpose

Glossary Review reviews glossary XLSX files generated by Glossary Extraction
against reference TXT files, writes a final reviewed XLSX, and lets the user
import that final table into the Translation glossary.

It is a standalone top-level module. It is not part of General Tools and does
not automatically start Translation.

## Navigation

Glossary Review pages:

- Run
- Review
- Presets
- Prompt
- Settings

The shared Model page owns API profiles. Glossary Review stores only its active
model id in app settings.

## Settings

Persisted under `GlossaryReviewSettings`:

- `input_folder`
- `selected_xlsx_path`
- `selected_reference_paths`
- `source_language`
- `target_language`
- `output_filename`
- `novel_background`
- `review_rounds`
- `batch_size`
- `retry_attempts`
- `timeout_seconds`
- `auto_open_output_folder`

`output_filename` defaults to `glossary-review-final.xlsx`, and the final XLSX
is written under `input_folder`. The workflow only accepts XLSX glossary input.
Reference TXT files are optional at the contract level but strongly recommended
in the product workflow. Glossary Review has no separate output-folder setting.

`retry_attempts` is Glossary Review's module-level transport retry budget for
failed LLM requests: timeout, provider 5xx, or transport errors. This existing
field is intentionally retained instead of using model-profile retry settings.
Backoff timing is internal and fixed. Unlike Translation and Glossary
Extraction, Glossary Review currently uses this value directly without the
same internal cap. HTTP 429 is handled by API-key rotation / key-pool cycling
when multiple keys are available; it is not treated as a normal same-key
transport retry.

The input folder row keeps a frontend-local recent-folder history. Selected
XLSX and reference paths are still controlled by discovery and explicit user
selection, not by folder history.

## Settings Discovery

`glossary_review.discover_inputs` scans the configured input folder and returns
candidate XLSX and TXT files.

When multiple glossary candidates exist, the user selects one XLSX. Reference
TXT files support multi-select. The app does not guess among multiple
candidates.

When Glossary Extraction's Send to Review action lands here, it sets
`input_folder`, clears explicit selections, and lets this discovery path select
fresh candidates. It also copies the extraction novel background into the review
settings so the user does not need to paste it again.

## Run Page

The Run page is execution/status only.

It shows:

- compact active configuration bar with preset, model, and prompt selectors
- quick-switch modals for preset, model, and prompt
- current task id
- round-aware progress
- completed, failed, remaining, elapsed, and average speed stats
- processed/running subtask counter with the longest running subtask age
- compact request-log toggle that opens a pop-out request log for model calls
  and retained failure records, including lifecycle phase, last activity,
  provider error bodies, and throttled partial streaming responses without
  recording full prompts
- token stats
- failed subtask list
- Start, Stop, and Continue controls
- report/final-table actions only when the corresponding artifacts exist

It does not contain folder pickers, language selectors, provider credentials,
runtime-limit fields, or prompt editors.

`timeout_seconds` remains a per-provider-request timeout. The longest-running
subtask age shown on the Run page is wall-clock runtime for the whole workflow
subtask and can include bounded request retries/backoff or review-round work.

## Task Lifecycle

Glossary Review uses the shared async task runtime:

- `glossary_review.start_task`
- `glossary_review.pause_task`
- `glossary_review.stop_task`
- `glossary_review.continue_task`
- `glossary_review.probe_continuable`
- `glossary_review.read_snapshot`
- `glossary_review.read_request_events`
- `glossary_review.list_recent_tasks`
- `glossary_review.read_artifacts`
- `glossary_review.list_failed_subtasks`

Continue reuses task cache for stopped, paused, or failed tasks that still have
pending or failed subtasks.

## Prompt Page

Glossary Review prompt presets are managed through the shared prompt page with
`kind = "glossary_review"`.

Current behavior:

- system presets are read-only
- only the system preset matching the UI language is shown
- custom presets are editable
- prompt preview uses the same backend prompt path as the runner
- thinking guidance is system-level runtime behavior, not user preset text

## Presets Page

Glossary Review workflow presets are managed through the shared Presets page
with `kind = "glossary_review"`.

Current behavior:

- presets are user-created rows only
- each preset stores model, prompt, source language, and target language
- creating/editing uses a modal; model and prompt are selected from dropdowns
- applying a preset switches active model, active prompt, source language, and
  target language together
- presets are optional shortcuts; users can still change model, prompt, or
  languages individually after applying one
- duplicate creates a copy that can be edited before further use

## Backend Flow

1. Load the selected XLSX glossary rows.
2. Attach context snippets from the selected reference TXT files.
3. Run AI review in batches for `review_rounds`.
4. Skip later-round work when the review result has already stabilized.
5. Apply review actions to an in-memory final table.
6. Write `glossary-review-report.json` containing changed rows only.
7. Write the final XLSX to `output_filename`.
8. Write task metadata, artifacts, token usage, progress snapshots, and
   task-scoped request events, including failed attempts and model responses
   retained for request debugging.

Review actions can modify translation, modify category, or delete a row.
Category changes are written into the final spreadsheet.

## Report and Final Table

The change report contains only rows changed by review. Report cells are
copyable. Deleted report rows can be restored into the final table.

The Review page reads the final XLSX and supports:

- search
- sort by visible columns
- inline row editing
- multi-select and Select All
- Shift/Cmd-style selection
- bulk delete
- save-back to the final XLSX

Edits are written to the final spreadsheet, so importing after review uses the
latest saved table.

## Import Into Translation

The final XLSX can be imported into the Translation glossary from Glossary
Review.

If the Translation glossary already has rows, the user chooses:

- replace existing rows, then import
- append imported rows
- cancel

Imports deduplicate exact rows. A row is considered duplicate only when every
stored field matches.

## Output

Default final output:

```text
glossary-review-final.xlsx
```

Report output:

```text
glossary-review-report.json
```

Artifact payload includes:

- final XLSX path
- report path when changed rows exist
- processed row counts
- review round metadata

## Verification Focus

Glossary Review changes should usually verify:

- XLSX input loading
- candidate input discovery
- Send to Review handoff from Glossary Extraction
- TXT context attachment
- multi-round progress and stabilization skip behavior
- report contains changed rows only
- final XLSX preserves category updates
- restore deleted report rows
- final table editing, sorting, selection, and bulk delete
- replace/append import into Translation glossary
- exact-row deduplication on import
- stop/continue cache behavior

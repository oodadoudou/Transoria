Frontend UX hardening notes
===========================

This note tracks the frontend UX regression coverage added for the June 30,
2026 UX hardening pass.

Covered behavior:

- Settings reset now asks for confirmation before destructive module resets.
- Failed-subtask attribution prefers structured error codes and keeps message
  matching only as a fallback for older or provider-specific failures.
- TXT to EPUB preset/style labels come from locale catalogues. Backend labels
  remain fallback text for unknown future ids.
- The proofreading page restores the last active task, selected segment, and
  virtual-list scroll offset after navigation.

Implementation findings:

- The frontend previously had no automated test command. Vitest/jsdom was added
  as a lightweight regression layer for pure UX logic and small component tests.
- React Testing Library renders are cleaned up from src/vitest.setup.ts so tests
  do not leak DOM into later cases.
- jsdom does not provide the layout APIs used by the virtual list, so the setup
  file includes narrow ResizeObserver and scrollTo polyfills.
- Restored proofreading scroll state has to be applied after task data and the
  virtual list exist. The matching first persistence pass is skipped so initial
  render defaults do not overwrite the restored value.

Documentation limitation:

- Active docs under docs/ were already deleted in the worktree before this
  implementation. They were not restored or edited as part of this UX pass.
